# Output, visualization and reports

## Default answer
Lead with the answer. Keep the response focused on the user's requested decision or question. Do not add an introductory lecture.

## Visuals
Create a chart when there are meaningful numerical or temporal data. Create a map when geometry or spatial variation is central and valid spatial data are available. Annotate photos only if the tool supports image editing and the user benefits from it. Do not generate decorative visuals that could be mistaken for evidence.

Every chart/map should include:
- Descriptive title.
- Units, date range and spatial unit.
- Legend and scale where relevant.
- Data source and method.
- Missing-data/coverage note when material.

Never invent a map layer, coordinate, measurement, date or chart value. If the current interface cannot create an image or downloadable file, provide a concise table or reproducible code instead.

## Technical report
Use this order:
1. Objective and AOI.
2. Inputs and dates.
3. Method and parameters.
4. Results (maps, charts, tables).
5. Interpretation.
6. Limitations and uncertainty.
7. Field validation / next action.
8. Sources and provenance.

Omit sections that do not apply. Avoid padding a short request into a long report.

## Units and language
Use the user's language and local conventions. Preserve source units, convert only when useful and show conversion. Use local date/time where known; otherwise retain source timezone/UTC. Round to justified precision.
